# HANDS-001 Sample Featureの共通部品を作成する

## 1. 目的

Templateから、SampleAppのHome / History / SettingsをまとめるSample Featureと、そこから遷移する補助画面のPlaceholderを段階的に作成する。

この課題では、次の設計を実装で確認する。

- Feature単位のディレクトリ構成
- `presentation/common`に置くFeature共通部品
- `SampleGraph`によるRoute登録
- `SampleRoutes`によるRoute文字列集約
- `SampleNavigationComponents`による共通UI
- Route / Screenの分離
- Navigation ComposeのBack Stack制御

`Sample`は教材上のFeature名であり、実案件では業務上の責務を表す名前へ置き換える。

## 2. SampleAppとの対応

SampleAppでは、次の構成になっている。

```text
feature/sample/
  presentation/
    common/
      SampleGraph.kt
      SampleNavigationComponents.kt
      SampleRoutes.kt
      SampleOperationLogMessageFactory.kt
      SampleUiErrorMapper.kt
    home/
    history/
    settings/
```

この課題で作成するのは、まず次の3つである。

```text
feature/sample/presentation/common/
  SampleGraph.kt
  SampleRoutes.kt
  SampleNavigationComponents.kt
```

`SampleOperationLogMessageFactory`と`SampleUiErrorMapper`は、業務Featureの処理が必要になってから追加するため、この課題では作成しない。

Drawerの遷移先はSample Featureにコピーせず、各FeatureのRoute定義を利用する。

```text
feature/legal/presentation/
feature/license/presentation/common/
feature/versioninfo/presentation/
```

## 3. 利用者の最終的な振る舞い

### 3.1 初期表示

- アプリ起動時にHome画面を表示する
- HomeをBottom Navigationの選択状態として表示する
- TopAppBar左側にハンバーガーメニューを表示する
- 画面下部にBottom Navigationを表示する

### 3.2 Bottom Navigation

Bottom Navigationには次の3項目を表示する。

| 表示名 | 遷移先 |
|---|---|
| 履歴 | Sample History |
| Home | Sample Home |
| 設定 | Sample Settings |

「その他」はBottom Navigationに追加しない。

### 3.3 Navigation Drawer

Drawerには次の項目を表示する。

- プライバシーポリシー
- 利用規約
- ライセンス
- バージョン情報

この課題では、各遷移先の内容はPlaceholderでよい。

### 3.4 戻る操作

- Drawer表示中のBackでは、先にDrawerを閉じる
- Drawerが閉じている場合はNavigationのBackを実行する
- 同じBottom Navigation項目を連続選択してもRouteを重複させない

## 4. 共通レイアウト

```text
AppRoot
  └─ 共通Theme
      └─ AppNavHost
          ├─ sampleGraph(navController)
          │   ├─ SampleRoute
          │   ├─ SampleHistoryRoute
          │   └─ SampleSettingsRoute
          ├─ legalDocumentGraph()
          ├─ licenseGraph()
          └─ versionInfoGraph()

Sample Featureの各Route
  └─ ModalNavigationDrawer
      └─ Scaffold
          ├─ SampleTopBar
          ├─ Screen content
          └─ SampleBottomNavigation
```

画面の色、余白、Shape、Typographyは既存のCore UI Themeを利用する。画面ごとに独自のThemeを追加しない。

## 5. 共通制約

### Navigation

- Navigation Composeを利用する
- `AppNavHost`はFeature Graphの登録を中心にする
- `SampleGraph`はHome / History / SettingsのRouteを登録する
- `SampleRoutes`は`feature/sample/presentation/common`へ置く
- Legal / License / VersionInfoのRoute定義は各Feature側へ置く
- Route文字列をComposable内へ直接散在させない
- `NavController`はGraph / Route層だけで扱う
- `NavController`をScreenへ渡さない
- `NavController`をViewModelへ渡さない

### Common UI

`SampleNavigationComponents.kt`には、次の表示部品をまとめる。

- `SampleTopBar`
- `SampleDrawerContent`
- `SampleBottomNavigation`
- Bottom Navigation item定義
- Drawer item定義

共通UI部品は表示とクリック通知を担当し、Navigationの実行は呼び出し側へ委譲する。

### Screen

- Screenは表示と操作通知に集中させる
- ScreenからUseCase、Repository、Gateway、DAO、APIを呼び出さない
- ScreenはNavigationの実装詳細を知らない
- Placeholder画面にも業務処理を追加しない

### 業務処理

この課題では、次を追加しない。

- UiState / UiEvent / UiMessage / UiEffect
- ViewModel
- UseCase
- Repository / Gateway
- DataStore
- Room
- API通信
- 操作ログ保存

Drawerの開閉やNavigation状態など、画面シェルに必要なUI状態はComposable層で管理する。

### Resource

- 利用者向け文言は`strings.xml`または既存のResource方針に従う
- Screenや共通Composableへ日本語文言を直接埋め込まない
- 既存のMaterial Iconsを優先する
