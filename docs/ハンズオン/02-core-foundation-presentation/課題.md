# HANDS-002 課題

## 課題概要

Templateに含まれるCore Foundation / Presentationを読み解き、後続Featureを同じルールで実装できる状態にする。

Coreを再実装する課題ではない。既存のCore実装をSampleAppと比較し、契約に反する独自変更を入れずに利用方法を整理する。

## 課題範囲

### 対象Module

- `:core:foundation`
- `:core:presentation`

### 対象外

- Android依存のResource、Logger、Time、Coroutine実装
- Compose共通UI、Theme、Dialog、Loading
- DataStore、Room、Retrofit、License
- Feature固有のViewModel、UseCase、Repository
- テストコードの追加実装

これらは対応表の後続Stepで扱う。

## 実施内容

1. Moduleの依存方向と公開範囲を確認する
2. `AppResult`、`AppError`、`UiError`、Validationの責務を確認する
3. `UiState`、`UiEvent`、`UiMessage`、`UiEffect`、`Reducer`の関係を確認する
4. `BaseViewModel`のStateFlow、SharedFlow、Channel、Reducer接続を確認する
5. SampleAppと実装を比較し、不要な独自差分がないことを確認する
6. 理解を助けるKDocやREADMEの補足だけを追加する

## 禁止事項

- TemplateにすでにあるCoreクラスを別名で作り直さない
- `Result<T>`や独自のEvent基底クラスを追加しない
- `BaseViewModel`へLoading、Error、UseCase実行などの自動処理を追加しない
- ReducerからAPI、DB、Navigation、Dialogを呼び出さない
- ViewModelへ`NavController`、`Context`、Composableを渡さない
- SampleAppと異なる実装を「学習用」として残さない

## 成果物

- Coreの責務を整理した自己レビュー結果
- 必要に応じたKDocまたはREADMEの補足
- 回答側では、Core実装がSampleAppと一致していることの確認記録
