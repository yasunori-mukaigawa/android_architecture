# 1. 対象概要

## 1.1 対象画面 / 機能

| ID | Feature | 画面 / 機能 |
|---|---|---|
| F-01 | sample | Home |
| F-02 | sample | History |
| F-03 | sample | Settings |
| F-04 | operationlog | 操作履歴保存・取得・削除 |
| F-05 | legal | Privacy Policy / Terms of Service |
| F-06 | license | License List / License Detail |
| F-07 | versioninfo | Version Info |
| F-08 | app | AppRoot / AppNavHost / Database / DataStore |

## 1.2 画面一覧 / Route 対応

| Route | 画面 | 引数 |
|---|---|---|
| `sample` | Sample Home | なし |
| `sample/history` | Sample History | なし |
| `sample/settings` | Sample Settings | なし |
| `license` | License List | なし |
| `license/{licenseId}` | License Detail | `licenseId` |
| `legal/{type}` | Legal Document | `type` |
| `version_info` | Version Info | なし |

Route 引数は安定した文字列値を利用し、生成時に encode する。Graph で argument を復元し、Route へ渡す。

## 1.3 画面の責務

- Screen は UiState の描画と UiEvent の通知を行う。
- Route は Hilt ViewModel の取得、State / Effect の購読、Navigation、Dialog、Snackbar、外部 URI 起動を行う。
- ViewModel は Event を処理し、UseCase の結果を Message / Effect へ変換する。
- UseCase は UiState と Android UI に依存しない。

## 1.4 前提条件 / 制約

- ViewModel へ `Context`、`NavController` を注入しない。
- Screen から UseCase、Repository、Gateway、DAO、API を直接呼び出さない。
- UiState に Entity、DTO、Raw resource、単発処理を保持しない。
- Reducer は副作用を持たない。
- Kotlin 標準 `Result<T>` ではなく `AppResult<T>` を利用する。
- Interface 名に `I` prefix を付けない。

## 1.5 基本設計との対応

| 基本設計 | 詳細設計 |
|---|---|
| State / Event / Message / Effect | 各 Feature の型定義と遷移表 |
| UseCase | UseCase 一覧、入出力、処理手順 |
| Repository | Domain 契約、Data 実装、Mapper |
| 画面遷移 | Routes / Graph / Route |
| エラー | AppError、UiError Mapper、表示 Effect |

# 3. 状態設計

## 3.1 方針

- State を画面描画の唯一の入力とする。
- Mutable State は BaseViewModel 内に閉じる。
- State 更新は `dispatch(message)` から Reducer 経由で行う。
- Derived property は現在 State から決定できる値に限定する。
- Navigation / Dialog / Snackbar / 外部 URI は State に含めない。

## 3.2 Home State

```kotlin
data class SampleUiState(
    val isLoading: Boolean,
    val greetingMessage: String = "",
    val dateText: String = ""
) : UiState
```

### 状態遷移

| 現在 | Message | 次 |
|---|---|---|
| 初期 | `LoadStarted` | `isLoading=true` |
| Loading | `HomeHeaderUpdated` | 挨拶・日付更新 |
| Loading | `LoadSucceeded` | `isLoading=false` |
| Loading | `LoadFailed` | `isLoading=false`、エラー表示 |

## 3.3 History State

```kotlin
data class SampleHistoryUiState(
    val isLoading: Boolean,
    val searchQuery: String,
    val selectedFilter: SampleHistoryFilter,
    val items: List<SampleHistoryItemUiState>,
    val screenErrorMessage: String?
) : UiState
```

`visibleItems` は `selectedFilter` と `searchQuery` から計算する。検索対象は title と summary、Error filter は `filter == Error` または `isError == true` とする。

## 3.4 Settings State

保持する値は次のとおり。

- `isLoading`
- `notificationEnabled`
- `confirmOnLoginEnabled`
- `keepCacheEnabled`
- `themeMode`
- `themeId`
- `themeModeOptions`
- `themePresetOptions`
- `screenErrorMessage`

設定値の初期値は Boolean 3項目が true、ThemeMode が System、ThemeId が Default である。

## 3.5 License State

### List

```kotlin
data class LicenseListUiState(
    val isLoading: Boolean = true,
    val searchKeyword: String = "",
    val items: List<LicenseItemUiState> = emptyList(),
    val errorMessage: String? = null
)
```

`visibleItems` は name または licenseName の大文字小文字を無視した部分一致で計算する。

### Detail

```kotlin
data class LicenseDetailUiState(
    val isLoading: Boolean = true,
    val name: String = "",
    val licenseName: String = "",
    val copyright: String = "",
    val licenseText: String = "",
    val errorMessage: String? = null
)
```

## 3.6 Legal State

```kotlin
data class LegalDocumentUiState(
    val screenState: LegalDocumentScreenState,
    val title: String,
    val markdown: String,
    val errorMessage: String?
) : UiState
```

`LegalDocumentScreenState` は Loading、Loaded、Error を表す。

## 3.7 Version Info State

保持する値は、画面状態、アプリ名、説明、公開チャネル、現在バージョン、最新バージョン、ビルド番号、最終確認日時、確認状態、状態タイトル、状態メッセージ、外部ボタン表示条件、エラーメッセージとする。

Domain の `VersionInfo` をそのまま公開せず、表示文字列とボタン表示条件へ変換した値を保持する。

# 5. 処理設計

## 5.1 BaseViewModel

BaseViewModel は次の責務だけを持つ。

```kotlin
abstract class BaseViewModel<S, E, M, F>(
    initialState: S,
    reducer: Reducer<S, M>
) : ViewModel()
```

### 保持・公開

- `MutableStateFlow<S>` を private に保持する。
- `StateFlow<S>` を public に公開する。
- `MutableSharedFlow<F>` を private に保持する。
- `SharedFlow<F>` を public に公開する。
- `Channel<E>(Channel.BUFFERED)` を private に保持する。

### 公開・protected API

| API | 可視性 | 責務 |
|---|---|---|
| `uiState` | public | StateFlow 公開 |
| `uiEffect` | public | SharedFlow 公開 |
| `sendEvent(event)` | public | Event を Channel へ送る |
| `handleEvent(event)` | protected abstract suspend | Feature のイベント処理 |
| `dispatch(message)` | protected | Reducer で State 更新 |
| `emitEffect(effect)` | protected suspend | Effect 発行 |
| `stateValue` / `currentState()` | protected | 現在 State 参照 |

### BaseViewModel が行わないこと

- 自動 Loading 制御
- AppError の自動 UI 変換
- UseCase 実行ラッパー
- Dialog / Navigation の自動実行
- 汎用 ErrorHandler の強制
- 全 Feature 共通の Busy 制御

## 5.2 Home 処理

### UseCase

`GetSampleHomeHeaderUseCase` は、`DateTimeProvider` から現在時刻を取得し、`SampleGreetingPolicy` で挨拶種別を判定して `SampleHomeHeader` を返す。表示文言や日付書式は Presentation 側で解決する。

### ViewModel

1. `Initialize` 受信
2. `LoadStarted` を dispatch
3. Home Header UseCase を実行
4. 成功時、Formatter で表示値へ変換
5. `HomeHeaderUpdated`、`LoadSucceeded` を dispatch
6. Home 表示ログを保存
7. 失敗時、UiError へ変換し `LoadFailed` と Dialog Effect を発行

## 5.3 History 処理

1. `Initialize` で購読 Job を開始する。
2. 既存 Job がある場合はキャンセルして二重購読を防ぐ。
3. OperationLog を `SampleHistoryItemUiState` へ変換する。
4. `LoadSucceeded` を dispatch する。
5. 検索・分類 Event では State 更新 Message を dispatch する。
6. 取得失敗時はエラー Message と Dialog Effect を発行する。

## 5.4 Settings 処理

Settings ViewModel は、Sample Settings と Theme Settings を別の購読として扱い、初期化時に既存 Job をキャンセルする。

設定変更は現行実装では楽観的に表示を更新してから UseCase を呼び出す。保存失敗時の表示を保存前へ戻すかどうかは、案件適用時に確定する。

## 5.5 Legal 処理

1. Graph が Route 引数を `LegalDocumentType` へ変換する。
2. `OnAppear` で対象種別を保持する。
3. UseCase が Repository を通じて raw resource を取得する。
4. 成功時はタイトル・Markdown を State へ設定する。
5. 失敗時は Error State と Dialog Effect を発行する。
6. Retry は最後の種別を再利用する。

## 5.6 License 処理

- List ViewModel は一覧取得、検索、Detail 遷移を扱う。
- Detail ViewModel は Route から受けた ID の詳細取得を扱う。
- Provider が返す LicenseInfo / LicenseDetail を UiState 表示値へ変換する。
- 不正 ID、未存在、取得失敗は Feature の Error Mapper で表示へ変換する。

## 5.7 Version Info 処理

1. AppInfoProvider から現在のアプリ情報を取得する。
2. LatestVersionRepository から最新情報を取得する。
3. `versionCode` を比較して `Latest`、`UpdateAvailable`、`CheckFailed` を決定する。
4. VersionInfoUiMapper が表示用 State を生成する。
5. `OpenExternalUri` は Route が Android Intent へ接続する。

## 5.8 Message 一覧

| Feature | Message の例 |
|---|---|
| Home | `LoadStarted`、`HomeHeaderUpdated`、`LoadSucceeded`、`LoadFailed` |
| History | `LoadStarted`、`LoadSucceeded`、`LoadFailed`、`SearchQueryUpdated`、`FilterUpdated` |
| Settings | `LoadStarted`、`LoadSucceeded`、設定値更新、保存成功・失敗、Theme 更新 |
| Legal | `LoadStarted`、`LoadSucceeded`、`LoadFailed` |
| License | `LoadStarted`、`LoadSucceeded`、`LoadFailed`、検索更新 |
| Version | `LoadStarted`、`LoadSucceeded`、`LoadFailed` |

Message は Reducer が State を更新するために必要な値だけを保持する。

## 5.9 Effect 一覧

| Effect | 用途 |
|---|---|
| `NavigateBack` | 前画面へ戻る |
| `NavigateHome` / `NavigateSettings` | Sample 内遷移 |
| `NavigateToDetail(id)` | License 詳細などへ遷移 |
| `ShowDialog(title, message)` | エラー・確認表示 |
| `ShowSnackbar(message)` | 保存成功などの短時間通知 |
| `OpenExternalUri(uri)` | Store / App Info ページ起動 |

# 6. クラス設計

## 6.1 クラス一覧

| 層 | クラス・型 | 役割 |
|---|---|---|
| UI | `*Screen` | State 描画・Event 通知 |
| Presentation | `*Route` / `*Graph` | 画面接続・副作用・遷移 |
| Presentation | `*ViewModel` | Event 解釈・UseCase 接続 |
| Presentation | `*Reducer` | Message から State 生成 |
| Application | `*UseCase` | アプリケーション操作 |
| Application | `*Facade` | 画面単位の依存窓口 |
| Domain | Model / Policy / Repository | 意味・判定・契約 |
| Data | RepositoryImpl / Mapper / Entity / DAO | 外部・保存方式の具体化 |
| Core | Provider / Store / Logger / UI 部品 | 共通契約・実装 |

## 6.2 Screen

- `uiState` と `onEvent` を引数に受け取る。
- ViewModel を取得しない。
- NavController を参照しない。
- UseCase / Repository / Gateway / DAO / API を呼ばない。
- `uiState` の値に応じて描画する。
- ユーザー操作を `onEvent` へ渡す。

## 6.3 Route

- `hiltViewModel()` で ViewModel を取得する。
- `collectAsStateWithLifecycle()` で State を購読する。
- `LaunchedEffect` で初期 Event と Effect 購読を開始する。
- NavController を利用して Navigation を実行する。
- DialogUiState、SnackbarHostState、外部 URI 起動へ Effect を接続する。
- Screen へ State と Event callback を渡す。

## 6.4 ViewModel

- `BaseViewModel<S, E, M, F>` を継承する。
- `handleEvent` で Event を処理する。
- UseCase / Facade を呼び出す。
- 成功・失敗を Message と Effect へ変換する。
- Reducer を直接呼ばず `dispatch` を利用する。
- State を直接 mutate しない。

## 6.5 Facade

画面の依存が増えた場合、UseCase 群は `*UseCaseFacade`、Mapper / Formatter / ErrorMapper / Logger 等は `*PresentationFacade` にまとめる。Facade は依存を隠すが、処理そのものを巨大化させない。

## 6.6 UseCase

- 1つのアプリケーション操作を表す。
- UiState を入力にしない。
- UI 文言、Compose、NavController に依存しない。
- Repository / Provider / Gateway を契約経由で利用する。
- 失敗を `AppResult.Failure(AppError)` として返す。

## 6.7 Repository / Gateway / Provider

- Repository は保存方式やデータ取得方式を隠蔽する。
- Gateway は API、SDK、外部サービスを隠蔽する。
- Provider は時刻、文字列、AppInfo、License などの環境依存情報を提供する。
- Interface は `I` prefix を付けず、契約名と実装名を分離する。

## 6.8 Reducer

Reducer は次の契約を満たす。

```kotlin
fun interface Reducer<S : UiState, M : UiMessage> {
    fun reduce(currentState: S, message: M): S
}
```

Reducer 内で禁止する処理は、I/O、時刻取得、ログ、Navigation、Effect 発行、例外変換である。

# 7. シーケンス設計

## 7.1 基本シーケンス

```text
User -> Screen : 操作
Screen -> Route/ViewModel : UiEvent
ViewModel -> UseCase : 処理要求
UseCase -> Repository/Provider : 取得・保存
Repository/Provider --> UseCase : AppResult
UseCase --> ViewModel : AppResult
ViewModel -> Reducer : UiMessage
Reducer --> ViewModel : UiState
ViewModel -> Route : UiEffect
Route -> Screen/Android : 表示・遷移・起動
```

## 7.2 Home 初期化

```text
SampleRoute -> SampleViewModel : Initialize
SampleViewModel -> GetSampleHomeHeaderUseCase : invoke
GetSampleHomeHeaderUseCase -> DateTimeProvider : current
GetSampleHomeHeaderUseCase -> SampleGreetingPolicy : resolve
GetSampleHomeHeaderUseCase --> SampleViewModel : Success(header)
SampleViewModel -> SampleReducer : HomeHeaderUpdated / LoadSucceeded
SampleViewModel -> SaveOperationLogUseCase : HomeDisplayed
```

## 7.3 Settings 保存

```text
SampleSettingsScreen -> SampleSettingsRoute : NotificationChanged
SampleSettingsRoute -> SampleSettingsViewModel : sendEvent
SampleSettingsViewModel -> Update...UseCase : invoke
Update...UseCase -> SampleSettingsRepository : update
SampleSettingsRepository -> PreferenceDataStore : putBoolean
PreferenceDataStore --> SampleSettingsRepository : completion / error
SampleSettingsViewModel -> Reducer : SaveSucceeded / SaveFailed
SampleSettingsViewModel -> Route : Snackbar / Dialog Effect
```

## 7.4 History 購読

```text
SampleHistoryViewModel -> ObserveOperationLogsUseCase : invoke
ObserveOperationLogsUseCase -> OperationLogRepository : observeRecent
OperationLogRepository -> RoomOperationLogLocalDataSource : observe
RoomOperationLogLocalDataSource -> OperationLogDao : observeRecent
OperationLogDao --> ViewModel : Flow<AppResult<List<OperationLog>>>
ViewModel -> SampleHistoryItemMapper : map
ViewModel -> Reducer : LoadSucceeded
```

## 7.5 Error 時

```text
UseCase --> ViewModel : AppResult.Failure(AppError)
ViewModel -> UiErrorMapper : map error
ViewModel -> Reducer : LoadFailed / SaveFailed
ViewModel -> Route : ShowDialog / ShowSnackbar
Route -> User : 表示
```

# 8. データ構造設計

## 8.1 データ分類

| 種別 | 例 | 利用範囲 |
|---|---|---|
| Domain | `SampleSettings`、`OperationLog`、`VersionInfo` | Domain / Application |
| UiState | `SampleUiState`、`VersionInfoUiState` | Presentation / UI |
| UiEvent | `SampleSettingsUiEvent` 等 | UI / Presentation |
| UiMessage | `LoadSucceeded` 等 | Presentation |
| UiEffect | `ShowDialog` 等 | Presentation / Route |
| Entity | `OperationLogEntity` | Room / Data |
| DTO | `LatestVersionDto` | API / Data |
| Raw | Markdown本文 | Resource / Data |

## 8.2 変換責務

| 変換 | 担当 |
|---|---|
| Entity -> Domain | Data Mapper |
| Domain -> Entity | Data Mapper |
| DTO -> Domain | API Mapper |
| Domain -> UiState | Presentation Mapper |
| AppError -> UiError / message | Feature Presentation Error Mapper |
| Filter / Domain value -> display string | Presentation Mapper / StringProvider |

## 8.3 AppResult

```kotlin
sealed interface AppResult<out T> {
    data class Success<T>(val value: T) : AppResult<T>
    data class Failure(val error: AppError) : AppResult<Nothing>
}
```

標準 Result は利用しない。`map`、`fold`、`onSuccess`、`onFailure`、`getOrNull`、`errorOrNull` は補助関数として利用できるが、失敗を隠す目的では利用しない。

## 8.4 AppError

| 型 | 保持情報 | 用途 |
|---|---|---|
| Validation | code、field、reason、cause | 入力不正 |
| Business | code、reason、cause | 業務条件不成立 |
| LocalStorage | code、cause | DataStore / Room 等 |
| Network | code、cause | 接続・通信失敗 |
| Api | code、statusCode、reason、cause | APIエラー |
| ApiInvalidResponse | code、reason、cause | 応答形式不正 |
| Unexpected | code、cause | 未分類例外 |

AppError は表示文言を保持せず、Presentation で UiError へ変換する。

# 9. データ設計

## 9.1 DataStore

`PreferenceDataStore` は Boolean / String / Int / Long / Float / StringSet の購読・保存・削除を提供する。AndroidX DataStore の生成ファイル名と Scope は App 側で決定する。

### 主な保存キー

| 用途 | 値 | 初期値 |
|---|---|---|
| Sample 通知 | Boolean | true |
| Sample ログイン時確認 | Boolean | true |
| Sample キャッシュ保持 | Boolean | true |
| Theme Mode | String | system |
| Theme ID | String | default |

## 9.2 Room

AppDatabase は `OperationLogEntity` と `OperationLogDao` を登録する。Entity は `operation_logs` テーブルへ保存し、発生日時、種別、結果に Index を持つ。

### DAO 操作

| 操作 | SQL上の方針 |
|---|---|
| observeRecent | occurred_at_millis DESC、id DESC、limit |
| findRecent | 同上の一回取得 |
| findByType | type 指定、日時降順 |
| insert | Room autoGenerate |
| deleteOlderThan | 閾値より古いレコードを削除 |
| deleteAll | 全レコード削除 |

## 9.3 OperationLog Domain

保存形式の文字列は Enum 名と分離した安定値を利用する。不明な保存値を読んだ場合は、Type は System、Result は Info へフォールバックする。

## 9.4 Legal Resource

`LegalDocumentType` と raw resource ID を Mapper で対応付ける。Repository は本文と表示タイトルを `LegalDocument` へ組み立て、Markdown 描画は UI に委譲する。

## 9.5 License Data

`core:license` の `LicenseProvider` がライセンス一覧・詳細を提供する。Feature は provider の具体実装を直接参照せず、UseCase を介して取得する。

## 9.6 Version Data

| データ | 取得元 |
|---|---|
| 現在の versionName / versionCode / packageName / channel | AppInfoProvider |
| 最新 versionName / versionCode | LatestVersionRepository |
| Store / App Info URI | AppExternalLinksProvider |
| 表示文言・状態 | VersionInfoUiMapper / StringProvider |

現行 DI は `FakeLatestVersionRepository` を標準利用し、`RetrofitLatestVersionRepository` は差し替え候補として存在する。

# 10. エラー設計

## 10.1 エラー検知箇所

| エラー | 検知・変換箇所 |
|---|---|
| Validation | Policy / UseCase |
| Room / DataStore 例外 | LocalDataSource / Repository |
| Network / API | Network / Gateway / Repository |
| Mapper 不整合 | Mapper / Repository |
| UI 表示文言 | Presentation Error Mapper |

## 10.2 Error -> UI 変換

Feature ごとに `*UiErrorMapper` または同等の Presentation 部品を持ち、AppError の分類に応じて title、message、supportMessage、actions を決定する。ViewModel は Mapper の結果を UiMessage / UiEffect へ渡す。

## 10.3 Screen / Effect の使い分け

| エラー内容 | State | Effect |
|---|---|---|
| 入力値エラー | 入力項目のエラー | 原則なし |
| 画面内に継続表示する読込エラー | errorMessage | 必要に応じてDialog |
| 保存成功 | 通常状態 | Snackbar |
| 保存失敗 | 画面エラー | Dialog |
| 戻る・遷移 | 変更なし | Navigation |
| 外部起動失敗 | 状態またはエラー | Dialog |

## 10.4 Coroutine Cancellation

CancellationException は通常の AppError として握りつぶさず、Coroutine のキャンセルとして上位へ伝播させる。Flow 購読 Job の再初期化時は既存 Job をキャンセルしてから新しい購読を開始する。

# 12. 非機能・補足

## 12.1 性能

- I/O は suspend / Flow として扱い、UI スレッドを直接ブロックしない。
- ViewModel 処理は viewModelScope に紐付ける。
- Application Scope は長寿命処理に限定する。
- Room の取得件数は Policy で補正する。

## 12.2 セキュリティ

- Context を ViewModel へ保持しない。
- ログ・操作履歴へ個人情報、トークン、秘密情報を出力しない。
- Error の cause、HTTP 応答全文、Stacktrace を画面へ出さない。
- 外部 URI は許可したリンクのみ起動する。

## 12.3 文字列

- UI 文字列は `strings.xml` に定義する。
- ViewModel は StringProvider 経由で表示文言を解決するか、Presentation Mapper から完成済み文字列を受け取る。
- Domain / UseCase は resource ID や Context を参照しない。

## 12.4 Theme

- `ThemeSettings` は ThemeMode と ThemeId を保持する。
- `BaseAppTheme` は AppRoot で一度適用する。
- `BaseThemeRegistry` は利用可能テーマと ThemePreset を解決する。
- 未知の ThemeId は Default へフォールバックする。

## 16.2 State / Event / Message / Effect遷移の読み方

各画面の処理は、次の順で記載する。

```text
Event
  -> ViewModel.handleEvent
      -> UseCase / Flow購読
          -> UiMessage dispatch
              -> Reducer
                  -> UiState
      -> 必要時にUiEffect
          -> RouteがNavigation / Dialog / Snackbar / URI起動
```

`UiMessage` はReducerに渡すState更新理由、`UiEffect` はStateに保持しない一回性処理である。EffectはRoute側で処理し、Reducerに副作用を持たせない。

## 16.3 Home遷移表

| Event | 前提 | 処理 | Message | Effect | State結果 |
|---|---|---|---|---|---|
| `Initialize` | 初期または再表示 | `GetSampleHomeHeaderUseCase`を実行 | `LoadStarted` -> `HomeHeaderUpdated` -> `LoadSucceeded` | なし | `isLoading=false`、挨拶・日付を保持 |
| `Initialize`失敗 | 読込中 | AppErrorをUiErrorへ変換 | `LoadFailed` | `ShowDialog` | エラー表示、`isLoading=false` |

UseCaseはDateTimeProviderで現在日時を取得し、`SampleGreetingPolicy`で挨拶種別を決定する。文言と日付書式は`SampleHomeHeaderFormatter`が解決する。Home表示ログの保存失敗はHome表示失敗へ連鎖させない。
