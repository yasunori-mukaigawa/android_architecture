# BaseArchitecture 永続化仕様書

## 1. 目的と範囲

本書は、現在のBaseArchitectureが端末内へ保存するデータの具体値、保存方式、読み書き責務、変換境界を定義する。

対象は以下とする。

- Sample設定値
- アプリ共通Theme設定
- Operation Log
- Room / DataStoreの共通契約

外部APIのサーバー側データや、案件固有の業務データは対象外とする。

## 2. DataStore

### 2.1 DataStore共通設定

| 項目 | 現行値 |
|---|---|
| 実装 | AndroidX Preferences DataStore |
| ファイル名 | `app_preferences` |
| 生成場所 | `app.datastore.PreferenceDataStoreModule` |
| Scope | Application単位のSingleton |
| CoroutineScope | `CoroutineScopeProvider.scope` |
| Android Context | `@ApplicationContext` |
| 公開契約 | `PreferenceDataStore` |
| 実装 | `AndroidPreferenceDataStore` |

DataStoreファイル名はApp側で決定し、Core Storageは型別の購読・保存・削除処理を提供する。RepositoryはDataStoreのkeyを外部へ漏らさない。

### 2.2 Sample設定キー

| 用途 | Key | 型 | 初期値 | Repository |
|---|---|---|---:|---|
| 通知 | `sample_notification_enabled` | Boolean | `true` | `SampleSettingsRepositoryImpl` |
| ログイン時確認 | `sample_confirm_on_login_enabled` | Boolean | `true` | `SampleSettingsRepositoryImpl` |
| キャッシュ保持 | `sample_keep_cache_enabled` | Boolean | `true` | `SampleSettingsRepositoryImpl` |

### 2.3 Theme設定キー

| 用途 | Key | 型 | 初期値 | Repository / DataStore |
|---|---|---|---|---|
| Theme Mode | `theme_mode` | String | `system` | `ThemeDataStore` |
| Theme ID | `theme_id` | String | `default` | `ThemeDataStore` |

Theme Modeの保存値は enum名である `System`、`Light`、`Dark`。Theme IDの標準値は `default`、現行サンプルの追加値は `dashboard`。未知値はSystemまたはDefaultへフォールバックする。

### 2.4 DataStore処理フロー

```text
ViewModel
  -> UseCase
      -> Repository
          -> PreferenceDataStore
              -> AndroidX DataStore Preferences
```

DataStore例外はRepositoryで `AppError.LocalStorage` へ変換する。CancellationExceptionはエラー結果へ変換せず、Coroutineのキャンセルとして再送出する。

## 3. Room Database

### 3.1 Database設定

| 項目 | 現行値 |
|---|---|
| Database class | `AppDatabase` |
| Database名 | `base_architecture.db` |
| Room version | `1` |
| Entity | `OperationLogEntity` |
| Fallback destructive migration | `false` |
| 生成Module | `DatabaseProvideModule` |
| DB scope | Singleton |
| Schema出力 | `app/schemas` |

Migrationを追加する場合は、Database versionを上げ、MigrationとSchemaを同時に更新する。現行構成では破壊的Migrationを許可しない。

### 3.2 `operation_logs` テーブル

| Column | Kotlin型 | Nullable | Default / 制約 | 用途 |
|---|---|---|---|---|
| `id` | Long | No | Primary Key / autoGenerate | DB採番ID |
| `type` | String | No | stable storage value | 操作種別 |
| `result` | String | No | stable storage value | 処理結果 |
| `title` | String | No | 必須 | ログタイトル |
| `summary` | String | Yes | null可 | 概要 |
| `detail` | String | Yes | null可 | 詳細 |
| `occurred_at_millis` | Long | No | epoch millis | 発生時刻 |
| `correlation_id` | String | Yes | null可 | 相関識別子 |

Indexは `occurred_at_millis`、`type`、`result` に設定する。

### 3.3 OperationLogの許可値

| Domain enum | Storage value | 不明値を読んだ場合 |
|---|---|---|
| Screen | `screen` | System |
| Action | `action` | System |
| Setting | `setting` | System |
| Upload | `upload` | System |
| Download | `download` | System |
| Search | `search` | System |
| Error | `error` | System |
| System | `system` | System |

| Domain enum | Storage value | 不明値を読んだ場合 |
|---|---|---|
| Success | `success` | Info |
| Failure | `failure` | Info |
| Warning | `warning` | Info |
| Info | `info` | Info |

### 3.4 DAO操作

| 操作 | 条件・並び順 | 戻り値 |
|---|---|---|
| `observeRecent(limit)` | `occurred_at_millis DESC, id DESC` | `Flow<List<OperationLogEntity>>` |
| `findRecent(limit)` | `occurred_at_millis DESC, id DESC` | `List<OperationLogEntity>` |
| `findByType(type, limit)` | type一致、日時降順 | `List<OperationLogEntity>` |
| `insert(entity)` | Room autoGenerate | 採番ID |
| `deleteOlderThan(thresholdMillis)` | 発生時刻が閾値未満 | 削除件数 |
| `deleteAll()` | 全件 | 削除件数 |

Query limitは `OperationLogQueryPolicy` で補正し、1未満の場合は既定値 `50` を利用する。

## 4. Operation Log保持

保持期間計算は `OperationLogRetentionPolicy` が担当する。日数が1未満の場合は既定値 `90日` を利用する。

現行サンプルでは保持期間削除UseCaseを提供するが、アプリ起動時などの自動実行契機は固定していない。

## 5. 変換境界

```text
OperationLogEntity <-> OperationLog
       ^                  ^
       |                  |
     Room DAO       Repository / UseCase
```

- EntityはData層だけで扱う。
- UiStateへは `SampleHistoryItemUiState` へ変換した値だけを渡す。
- DB例外は `DatabaseExecutor` / LocalDataSourceで `AppResult.Failure` へ変換する。
- UI表示文言はOperationLogの保存値と分離し、Presentation側のFactory / Mapperで解決する。
