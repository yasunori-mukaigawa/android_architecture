# BaseArchitecture 実装基盤・バージョン一覧

## 1. 目的

本書は、BaseArchitecture を同じビルド構成で再現するために必要な、SDK、Gradle Plugin、Kotlin、AndroidX、Compose、Core module の具体値を管理する。

設計思想や責務分離は [基本設計書.md](基本設計書.md) と [詳細設計書.md](詳細設計書.md) を参照し、本書では変更されやすい実装基盤の値を扱う。

## 4. Gradle Plugin適用

| 対象 | 適用Plugin |
|---|---|
| `:app` | Android Application、Kotlin Compose、KSP、Dokka、Hilt、OSS Licenses |
| `:core:*` | Android Library、Kotlin Compose、KSP、Dokka。Composeを使用するModuleのみCompose UI依存を持つ |
| Root | Dokka集約設定 |

Hilt PluginとOSS Licenses PluginのclasspathはRoot `build.gradle.kts`で管理する。Version catalogのPlugin aliasは、各Moduleの既存記述に合わせて使用する。

## 5. Module一覧

| Module | 役割 | Appからの参照 |
|---|---|---|
| `:app` | Application、AppRoot、Navigation、Feature、アプリ固有DI | - |
| `:core:foundation` | AppResult、AppError、Validation、共通契約 | appから参照 |
| `:core:presentation` | UiState / UiEvent / UiMessage / UiEffect / Reducer / BaseViewModel | appから参照 |
| `:core:platform` | StringProvider、日時、Logger、Dispatcher、Scope、AppInfo | appから参照 |
| `:core:storage` | DataStore、Room共通処理、Theme DataStore | appから参照 |
| `:core:network` | API応答、通信エラー、Interceptor | appから参照 |
| `:core:ui` | Theme、Dialog、Loading、Markdown | appから参照 |
| `:core:license` | OSS License ProviderとLicense Model | appから参照 |

Core Moduleは `:app` または Featureを参照しない。Feature固有のEntity、DAO、Repository実装は `:app` に置く。

## 6. 主要Gradleタスク

| コマンド | 用途 |
|---|---|
| `gradlew.bat test` | JVM Unit Testを実行 |
| `gradlew.bat assembleDebug` | Debug APKを生成 |
| `gradlew.bat :app:assembleDebug` | app Debug APKを生成 |
| `gradlew.bat dokkaGenerateHtml` | 全ModuleのDokka HTMLを集約 |
| `gradlew.bat :app:dokkaHtml` | app ModuleのDokka HTMLを生成 |

全Module版の出力先は `build/dokka/html/index.html`、app単体版は `app/build/dokka/html/index.html` とする。Dokka生成物はコミット対象にしない。

## 7. 再現時の注意

- Version catalogの値を先に確定してからGradle Syncを行う。
- Compose依存はCompose BOMを使用し、BOM管理対象の個別versionを追加しない。
- Room CompilerとHilt CompilerはKSPで処理する。
- `compileSdk` のminor API levelを利用できない環境では、SDK ManagerでAPI 36系の必要パッケージを確認する。
- 実サービス未接続のため、Version Infoの標準DIはFake Repositoryを利用する。
