# 文書情報

## 1. 文書の目的

本書は、`BaseArchitecture` Android アプリの要件を定義するものである。

本システムは、業務機能を提供する完成品ではなく、社内 Android アプリ開発で再利用するベースアーキテクチャと、その利用方法を確認するサンプルアプリである。

本書では、利用者および Feature 実装者から見て、何を実現する必要があるかを定義する。具体的なクラス構成、状態管理方式、module 分割、ライブラリの利用方法は基本設計書・詳細設計書で定義する。

## 2. 対象機能

- アプリ起動と共通画面表示
- Home 画面
- 操作履歴画面
- 設定画面
- Navigation Drawer
- プライバシーポリシー・利用規約表示
- OSS ライセンス一覧・詳細表示
- バージョン情報表示
- 設定値および操作履歴の端末内保存
- エラー表示、再試行、画面遷移、外部ページ起動
- Feature 実装者向け共通開発基盤

## 3. 対象範囲

### 3.1 対象

- 本サンプルアプリの利用者向け画面と振る舞い
- Feature 実装者が利用する共通開発基盤の提供目的
- 設定値、操作履歴、同梱文書、ライセンス情報の利用方針
- エラー、ログ、セキュリティ、性能、保守性に関する要求
- 基本設計・詳細設計へ引き継ぐ事項

### 3.2 対象外

- 実ユーザーの認証、ログイン、ログアウト
- 実案件固有の業務データおよび業務ルール
- 実際の通知配送
- ログイン時確認処理の本体
- キャッシュデータの取得・期限切れ・削除処理
- 操作履歴のサーバー同期、監査証跡としての法的保証
- 実際のアプリ更新処理
- 本番向け最新バージョン API
- 「その他」画面

# 1. 背景・目的

## 1.1 背景

Android アプリを複数案件で開発する場合、画面状態の扱い、エラー表示、Navigation、永続化、ログ、テストの方法が Feature ごとにばらつくと、実装者が変わるたびに設計判断が必要になる。

そのため、共通して利用できる基盤と、基盤の使い方を示す実行可能なサンプルが必要である。

## 1.2 目的

本システムは、次の目的を達成する。

- Feature 実装者が、既存のサンプルを参照して画面や機能を追加できるようにする
- 画面表示、利用者操作、処理結果、単発の画面処理を責務として分けられるようにする
- 保存方式や通信方式を画面の実装から切り離せるようにする
- Core を必要な範囲だけ他のアプリへ展開できるようにする
- テスト対象と責務の境界を明確にし、担当者が変わっても保守しやすくする

## 1.3 成功条件

| No | 成功条件 | 確認観点 |
|---|---|---|
| S-01 | アプリ起動後に Home 画面を利用できること | 起動・初期表示 |
| S-02 | Home、履歴、設定、Drawer 配下の画面を利用できること | 画面遷移 |
| S-03 | 設定を変更し、次回起動後も保存値を確認できること | 保存・復元 |
| S-04 | 操作履歴を確認、検索、分類できること | 履歴表示 |
| S-05 | 読み込みや保存の失敗時に、利用者が状態を把握し復旧操作を選択できること | 異常系 |
| S-06 | Feature 実装者が共通基盤の利用方法をサンプルから確認できること | 開発者受入 |
| S-07 | 実案件固有の機能を持たないサンプルとして、未接続部分が明示されていること | 適用範囲 |

# 2. システム概要

## 2.1 機能概要

BaseArchitecture は、Material 3 を利用した Android サンプルアプリである。起動後は Home を表示し、画面下部から履歴・Home・設定を切り替えられる。画面上部のメニューから、法務文書、OSS ライセンス、バージョン情報を確認できる。

設定値と操作履歴は端末内に保存する。文書とライセンス情報はアプリまたは導入ライブラリから取得する。バージョン情報は、現在のアプリ情報と最新確認結果を表示する。

## 2.2 利用者・権限

| 利用者 | 利用可否 | 主な操作 | 備考 |
|---|---|---|---|
| サンプル利用者 | 可 | 画面表示、設定変更、履歴確認 | 認証なし |
| Feature 実装者 | 可 | サンプル参照、Core 利用、機能追加 | 開発上の利用者 |
| 管理者 | 対象外 | 業務権限管理 | 本サンプルでは扱わない |

## 2.3 動作環境

| 項目 | 内容 |
|---|---|
| OS | Android |
| 対象 SDK | minSdk 29、targetSdk 36、compileSdk 36.1（現行ソース） |
| UI | Jetpack Compose / Material 3 |
| 保存 | 端末内保存 |
| ネットワーク | バージョン確認の実サービス接続は未確定 |

## 2.4 システム構成

本システムは、アプリ固有の機能と、再利用する共通機能を分離する。具体的な module 間依存と実装方式は基本設計書で定義する。

| 構成 | 役割 |
|---|---|
| アプリ本体 | 画面、Feature、アプリ固有の保存・Navigation・DI |
| 共通基盤 | 結果、エラー、状態管理、実行環境、保存、通信、UI、ライセンス |
| 端末内保存 | 設定値、操作履歴 |
| 同梱リソース | 法務文書、表示文言 |

## 2.5 前提条件

- アプリが端末へインストールされ、起動できること
- Android の対象 SDK を満たす端末またはエミュレーターで実行すること
- 法務文書が配布物へ同梱されていること
- OSS ライセンス情報を生成・取得できる構成であること
- 本サンプルではログイン済み利用者を前提としないこと

## 2.6 制約条件

- 本サンプルの設定画面は設定値の保存までを対象とし、実際の通知・認証確認・キャッシュ処理は対象外とする
- 最新バージョン情報の取得元は現行では Fake を利用し、本番サービスの仕様は未確定とする
- 個人情報や認証情報を操作履歴・アプリログへ保存しない
- 画面の振る舞いを定義する要件と、実装方式を定義する設計を混在させない

# 3. 業務要件

## 3.1 業務要件一覧

| No | 業務要件 | 説明 | 優先度 |
|---|---|---|---|
| B-01 | アプリの主要画面を利用できること | 利用者は Home、履歴、設定を切り替えられる | 必須 |
| B-02 | 補助情報を確認できること | 利用者は法務文書、ライセンス、バージョン情報を確認できる | 必須 |
| B-03 | 設定を保持できること | 利用者は設定を変更し、次回起動後も確認できる | 必須 |
| B-04 | 操作の履歴を確認できること | 利用者は主要な画面表示、設定変更、エラーを確認できる | 必須 |
| B-05 | 問題発生時に復旧方法を選択できること | 利用者は再試行、確認、画面離脱などを選択できる | 必須 |
| B-06 | 共通基盤を再利用できること | Feature 実装者は既存の責務分離方針を参照できる | 必須 |

## 3.2 業務ルール

| No | ルール | 内容 | 備考 |
|---|---|---|---|
| BR-01 | 時間帯別の挨拶 | 05:00以上12:00未満は朝、12:00以上18:00未満は昼、18:00以上05:00未満は夜として表示する | Home |
| BR-02 | 履歴の新しい順表示 | 操作履歴は発生日時の新しい順に表示する | 履歴 |
| BR-03 | 履歴の分類 | すべて、操作、設定、エラーを選択できる | 履歴 |
| BR-04 | 設定の初期値 | 通知、ログイン時確認、キャッシュ保持は初期状態を ON とする | 設定 |
| BR-05 | テーマの初期値 | 明暗モードはシステム設定、プリセットは標準とする | 設定 |
| BR-06 | 空の操作履歴 | 表示対象がない場合は空表示を示す | 履歴 |

## 3.3 業務フロー概要

1. 利用者がアプリを起動する
2. システムが共通表示と Home を表示する
3. 利用者が Home、履歴、設定、Drawer のいずれかを操作する
4. システムが設定、文書、ライセンス、操作履歴など必要な情報を読み込む
5. 利用者が検索、分類、設定変更、再試行などを行う
6. システムが結果を画面へ反映し、必要な履歴を保存する
7. 処理に失敗した場合は、状況と利用者が取れる復旧方法を表示する

## 3.4 業務上の例外・中断

| No | 状況 | 期待動作 | 備考 |
|---|---|---|---|
| EX-01 | 端末内データの読み込み失敗 | エラーを表示し、再試行または画面継続を可能にする | 対象画面による |
| EX-02 | 設定の保存失敗 | 保存失敗を通知し、利用者が状況を把握できるようにする | 実動作への反映は対象外 |
| EX-03 | 文書の読み込み失敗 | エラーを表示し、再試行できるようにする | 法務文書 |
| EX-04 | ライセンス情報の取得失敗 | エラーを表示し、一覧または詳細の復旧導線を示す | ライセンス |
| EX-05 | 最新バージョン確認失敗 | 現在のアプリ情報を可能な範囲で表示し、再確認できるようにする | バージョン情報 |
| EX-06 | 外部ページを開けない | エラーを通知し、アプリ内画面を継続する | 外部 URI |

## 4.2 機能別詳細要件

### 4.2.1 Home 機能

- Home を開いた時点の端末時刻に応じて挨拶を表示すること
- Home を開いた時点の日付を表示すること
- 読み込み中であることを表示できること
- 読み込みに失敗した場合は利用者へエラーを通知できること
- Home 表示を操作履歴へ記録できること

### 4.2.2 操作履歴機能

- 保存済みの操作履歴を新しい順で表示すること
- 履歴のタイトルまたは概要を入力文字列で検索できること
- すべて、操作、設定、エラーの分類を選択できること
- 今日、昨日などの日付単位で履歴を確認できること
- 表示対象がない場合は空表示を示すこと
- 読み込みに失敗した場合はエラーを通知できること

### 4.2.3 設定機能

- 通知を ON/OFF 変更できること
- ログイン時に確認を ON/OFF 変更できること
- キャッシュを保持を ON/OFF 変更できること
- テーマモードをシステム設定、ライト、ダークから選択できること
- テーマプリセットを登録済みの候補から選択できること
- 設定変更を保存できること
- 保存した設定を画面へ反映できること
- 設定保存の成功・失敗を利用者へ通知できること

### 4.2.4 Drawer・補助情報機能

- Drawer を開閉できること
- Drawer からプライバシーポリシーを開けること
- Drawer から利用規約を開けること
- Drawer からライセンス一覧を開けること
- Drawer からバージョン情報を開けること

### 4.2.5 法務文書機能

- プライバシーポリシーを表示できること
- 利用規約を表示できること
- 文書の読み込み中・完了・失敗を利用者が判別できること
- 読み込み失敗時に再試行できること

### 4.2.6 ライセンス機能

- OSS ライセンス一覧を表示できること
- ライセンス名またはライブラリ名で検索できること
- 一覧から詳細を開けること
- 詳細で名称、ライセンス種別、著作権、本文を確認できること
- ライセンス情報が取得できない場合はエラーを通知できること

### 4.2.7 バージョン情報機能

- アプリ名、説明、現在のバージョン、ビルド番号、公開チャネルを表示できること
- 最新確認日時を表示できること
- 最新版、更新あり、確認失敗を区別して表示できること
- 最新版でない場合はストアページを開く導線を提供できること
- アプリ情報ページを開く導線を提供できること
- 最新情報を再確認できること
- 外部ページを開けない場合はエラーを通知できること

## 4.3 構成別要件

| 構成 | 利用可能機能 | 利用不可機能 | 備考 |
|---|---|---|---|
| 標準アプリ構成 | 全サンプル機能 | なし | 現行構成 |

# 8. ログ要件

## 8.1 ログ記録方針

- 主要な画面表示、設定変更、処理失敗を後から確認できること
- ログは障害解析に必要な範囲で記録すること
- 個人情報、認証情報、アクセストークンを操作履歴・アプリログへ保存しないこと
- ログ記録に失敗しても、本来の画面操作を不要に失敗させないことを基本とする

## 8.2 ログ種別

| ログ種別 | 内容 |
|---|---|
| 画面 | Home などの画面表示 |
| 操作 | 利用者による主要操作 |
| 設定 | 設定値の変更 |
| エラー | 保存・取得・外部連携等の失敗 |
| システム | アプリ内部の処理 |

## 8.3 ログイベント一覧

| No | イベント | タイミング | 結果 |
|---|---|---|---|
| L-01 | Home 表示 | Home を表示した時 | 情報または成功 |
| L-02 | 設定変更 | 設定値を変更した時 | 成功 |
| L-03 | 設定保存失敗 | 設定保存に失敗した時 | 失敗 |
| L-04 | 取得・表示失敗 | 主要データの取得に失敗した時 | 失敗 |

## 8.4 ログ項目

| 項目 | 内容 | 必須 |
|---|---|---|
| 識別子 | ログを識別する値 | 必須 |
| 種別 | 画面、操作、設定、エラー等 | 必須 |
| 結果 | 成功、失敗、警告、情報 | 必須 |
| タイトル | 利用者が概要を把握する短い説明 | 必須 |
| 概要 | 補足説明 | 任意 |
| 詳細 | 障害調査用の情報 | 任意 |
| 発生日時 | 操作または処理の発生時刻 | 必須 |
| 相関識別子 | 一連の処理を関連付ける値 | 任意 |

- 画面の表示と操作を長時間の同期処理でブロックしないこと

- 保存・取得に失敗した場合、利用者が状況を把握できること
- 再試行可能な処理は再試行できること

- 設計意図を KDoc および Dokka HTML で確認できること

## 9.6 互換性要件

- 現行の Android SDK 条件で動作すること
- Android Studio からビルド・実行できること
- Core を利用しないアプリへ不要な機能を強制しないこと

# 10. 処理フロー

## 10.1 画面利用の基本フロー

```text
アプリ起動
  -> Home 表示
  -> Home / 履歴 / 設定を選択
  -> 必要な情報を読み込み
  -> 画面へ結果を表示
  -> 必要に応じて設定保存・履歴記録・補助画面遷移
```

## 10.2 設定変更フロー

```text
設定項目を変更
  -> システムが設定値を保存
  -> 保存結果を画面へ通知
  -> 成功時は保存完了を表示
  -> 失敗時はエラーと復旧方法を表示
```

## 10.3 履歴確認フロー

```text
履歴画面を表示
  -> 保存済み履歴を取得
  -> 日付単位で表示
  -> 検索文字列または分類を適用
  -> 対象がなければ空表示
```

## 10.4 分岐条件一覧

| No | 分岐条件 | Yes時 | No時 |
|---|---|---|---|
| D-01 | 画面表示に必要な情報を取得できたか | 内容を表示 | エラー表示 |
| D-02 | 設定保存に成功したか | 保存完了を通知 | 保存失敗を通知 |
| D-03 | 履歴が存在するか | 一覧を表示 | 空表示 |
| D-04 | 最新バージョン確認に成功したか | 最新・更新ありを判定 | 現在情報と確認失敗を表示 |

# 11. エラー・例外要件

## 11.1 エラー分類

| 分類 | 内容 | 利用者への表示 | 復旧方針 |
|---|---|---|---|
| 入力エラー | 入力値が条件を満たさない | 入力箇所または画面内 | 入力修正 |
| 業務エラー | 操作条件を満たさない | 画面内またはダイアログ | 条件見直し |
| 端末保存エラー | 設定・履歴の保存や読込失敗 | ダイアログ等 | 再試行・管理者確認 |
| 通信エラー | 通信できない | 通信確認・再試行案内 | 再試行 |
| 外部応答エラー | 外部情報が不正・失敗 | 応答エラー | 再試行・問い合わせ |
| 想定外エラー | 上記に分類できない失敗 | 汎用エラー | 再起動・調査 |

## 11.2 エラー要件一覧

| No | 状況 | 表示内容 | ログ | 復旧導線 |
|---|---|---|---|---|
| E-01 | 履歴・設定の読込失敗 | 読み込みに失敗したこと | 必要 | 再試行または画面継続 |
| E-02 | 設定保存失敗 | 保存できなかったこと | 必要 | 再操作 |
| E-03 | 法務文書読込失敗 | 文書を表示できないこと | 必要 | 再試行 |
| E-04 | ライセンス読込失敗 | ライセンスを取得できないこと | 必要 | 再試行・戻る |
| E-05 | バージョン確認失敗 | 最新情報を確認できないこと | 必要 | 再確認 |
| E-06 | 外部ページ起動失敗 | 外部ページを開けないこと | 必要 | 画面継続 |

## 11.3 エラー文言方針

- 利用者向け文言は、原因の分類と次の行動が分かる内容とする
- 内部例外名、スタックトレース、トークン等を画面へ表示しない
- 表示文言は文字列リソースで管理する
- 調査に必要なコードや原因は、利用者向け文言と分けて記録する
